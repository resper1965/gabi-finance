# gabi.brain · Runbook
Convenção: `BANCO=/var/lib/gabi-brain/gabi.db`. Comandos como usuário `gabibrain` (`sudo -u gabibrain …`) e `PY=/opt/gabi-brain/venv/bin/python`.

## Subir e parar
- Status: `systemctl is-active gabi-brain-api` → `active`.
- Reiniciar: `sudo systemctl restart gabi-brain-api`. Parar: `sudo systemctl stop gabi-brain-api`.
- Logs: `journalctl -u gabi-brain-api -n 50 --no-pager`.
- Socket: `ls -ld /run/gabi-brain` → `drwx------ gabibrain`; `ss -ltn | grep 8080` → **vazio** (não há porta TCP). Se aparecer qualquer `:8080`, **pare o serviço** e investigue.
- Chamar a API à mão (como root ou `gabibrain`): `curl --unix-socket /run/gabi-brain/api.sock http://localhost/api/eu -H 'Tailscale-User-Login: <login>'`.

## Acesso (quem entra)
- Listar: `$PY -m gabi.acesso --banco $BANCO listar`.
- Adicionar: `$PY -m gabi.acesso --banco $BANCO adicionar <login-tailscale> <pessoa_id> boss|familia_vip|terceiros`.
- Remover acesso: apagar a linha de `acesso` (sqlite3) e conferir `listar`. Sem login em `acesso`, a pessoa recebe 403.

## Revogar tudo (tokens de agentes)
- `curl --unix-socket /run/gabi-brain/api.sock -X POST http://localhost/api/revogar-tudo -H 'Tailscale-User-Login: <seu-login>' -H 'Content-Type: application/json' -d '{"confirmo": true}'` → `{"revogados": N}`. Sem `confirmo: true` → 400 e nada muda.

## Carregar o staging
- `$PY -m gabi.importar --banco $BANCO --staging /home/ricardo/gabi-brain-migracao/staging` → imprime contagens. Pode rodar de novo: não duplica. Registra uma rodada `importacao-staging`.

## Backup e restauração
- Diário 03:30 (`gabi-brain-backup.timer`), com teste de restauração. À mão: `$PY -m gabi.backup --banco $BANCO --destino /var/backups/gabi-brain --testar`.
- Resultado: `gabi-brain-AAAA-MM-DD.sqlite` (600) e uma rodada `backup`. Falha de integridade → rodada `erro` e código de saída 1.
- **Restaurar:** `sudo systemctl stop gabi-brain-api`; copiar o backup desejado para `$BANCO`; apagar `gabi.db-wal` e `gabi.db-shm`; `sudo systemctl start gabi-brain-api`; conferir `/api/saude`.
- Cópia fora da VPS: ver "Backup fora da VPS" abaixo (a VPS não guarda a única cópia).

## Backup fora da VPS {#backup-fora}
Pacote semanal criptografado, para o Ricardo puxar; a chave privada nunca fica na VPS.
1. **Uma vez, na sua máquina:** `gpg --quick-generate-key ricardo-gabi-backup` e `gpg --armor --export ricardo-gabi-backup > backup.pub`. Copie só a **pública** para a VPS: `sudo install -m 644 backup.pub /etc/gabi/backup.pub`. Guarde a privada (e uma cópia dela) fora da VPS.
2. Domingo 04:00 BRT (`gabi-brain-exportacao.timer`) gera `/var/backups/gabi-brain/exportacao/gabi-brain-AAAA-MM-DD.sqlite.gpg` (600; guarda os 8 últimos) e uma rodada `exportacao`. Sem `/etc/gabi/backup.pub` a unidade nem roda; se o teste de restauração falhar, nada é exportado e o sino avisa. À mão: `sudo systemctl start gabi-brain-exportacao`.
3. **Puxar (G17):** `scp vps:/var/backups/gabi-brain/exportacao/*.gpg ./` e conferir com `gpg --decrypt gabi-brain-AAAA-MM-DD.sqlite.gpg > teste.sqlite && sqlite3 teste.sqlite 'pragma integrity_check'` (deve dar `ok`).
4. **Restaurar a partir do pacote:** decifrar na sua máquina, copiar para a VPS e seguir "Restaurar" acima.

## Alertas
| Sinal | Significa | Ação |
|---|---|---|
| `/api/saude` com `db != "ok"` | banco corrompido | parar a API e restaurar o último backup |
| rodada `backup` com `status=erro` | backup ou restauração falhou | rodar à mão com `--testar` e ler a mensagem |
| `ultimo_backup` nulo ou com mais de 2 dias | timer parado | `systemctl status gabi-brain-backup.timer` |
| 403 para alguém que deveria entrar | login fora de `acesso` | `gabi.acesso adicionar` |

## Servidor MCP e tokens de agentes (Fase 1)
- O MCP escuta **só em 127.0.0.1:8081** (`gabi-brain-mcp.service`), Streamable HTTP em `/mcp`, e exige `Authorization: Bearer <token>`. Para agentes fora da VPS (Claude Code no seu Windows): `sudo tailscale serve --bg --https=8443 http://127.0.0.1:8081` (TLS na rede privada; o token continua obrigatório).
- Emitir (o token aparece **uma vez**; o banco guarda só o hash): `sudo -u gabibrain /opt/gabi-brain/venv/bin/python -m gabi.mcp.tokens emitir hermes fin` (escopos: `fin,docs,trabalho,pedidos,propostas,decisoes,envios,familia,sensivel,contatos`; trocar só os escopos de um token ativo, sem mudar o segredo: `... -m gabi.mcp.tokens escopos <id> fin,docs,...`). Você cola o token no agente; eu não o vejo.
- Listar: `... -m gabi.mcp.tokens listar` · Revogar um: `... revogar <id>` · Revogar todos: `POST /api/revogar-tudo` (ver acima).
- Cada chamada fica em `chamada_mcp` (token, ferramenta, escopo, status `ok|sem_escopo|erro|nao_autenticado`). Para ver: `sqlite3 $BANCO "select quando, ferramenta, status from chamada_mcp order by id desc limit 20"`.
- Só existem ferramentas de **leitura** (`docs/api.md#mcp`). Não há como enviar, pagar, apagar, aprovar nem ligar regra por MCP (R13).
- Se um agente receber `sem_escopo`, o token não tem o escopo da ferramenta: emita outro com o escopo certo (não amplie o de outro agente).

## Avisos de vencimento antecipados {#avisos-vencimento}
Além do aviso do dia (`vence_hoje`) e do de conta atrasada, o `gabi.avisos` (timer de 15 min) grava `vence_em_breve`: as contas `aberto`, `previsto` ou `debito_automatico` que vencem de amanhã até `avisos.antecedencia_dias` à frente (parâmetro JSON, padrão 3, de 1 a 14). Cada conta entra num aviso uma única vez (a que entra na janela depois, como boleto emitido tarde, sai no aviso do dia). O valor que ainda é estimativa (`valor_fonte` fora de `valores_do_mes`/`documento`/`fatura`: último pagamento ou padrão do mês) aparece como "≈ R$ X (estimado)"; a conta sem valor aparece como "sem valor"; débito automático vem marcado, para você garantir saldo. Na entrega o aviso é revalidado: conta já paga sai, e o valor real que chegou substitui o estimado (o aviso nunca anuncia o que deixou de ser verdade). Quando o valor real chega (cobrança confirmada ou pagamento conciliado) e difere em mais de 10% do estimado avisado, sai UM `valor_diferente` ("estimado R$ X, veio R$ Y"). Chegam pelo Telegram e pelo Hermes como os demais avisos.

## Avisos no Telegram (G15) {#telegram}
Desligado por padrão. Para ligar (é a sua exceção à R2): crie `/etc/gabi/telegram.env` (0640 `root:gabibrain`) com `TELEGRAM_BOT_TOKEN=...` e `TELEGRAM_CHAT_ID=...` (o bot vem do BotFather; o chat, do `getUpdates` depois de mandar uma mensagem ao bot). O `gabi-brain-telegram.timer` (5 min) envia os avisos ainda não lidos dos últimos 2 dias, no máximo 10 por rodada, em português, só com nome, valor e datas; marca `aviso.telegram_em` só depois do 200 e nunca reenvia. Para desligar: apague o arquivo. Teste à mão: `sudo systemctl start gabi-brain-telegram`.
**Aviso obsoleto não é enviado.** O gabi.brain é a fonte única da verdade: antes de entregar (Telegram, função `gabi.avisos.triar`), a condição é relida em três estados. `vale`: `conta_atrasada` com o compromisso ainda `atrasado`; `vence_hoje` com algum item ainda `aberto`/`previsto` (o texto sai do payload ATUAL, só com os itens abertos; itens casam por id do compromisso, ou nome+vencimento nos avisos antigos; entregue em outro dia, o item que virou `atrasado` sai e o `conta_atrasada` assume); `cobrada_apos_cancelar` com a assinatura ainda em `cancelar`. `resolvido` (pago, débito automático, vencimento movido, nenhum item aberto): o aviso é fechado sem envio. **Para esse aviso `telegram_em`/`entregue_em` significam "fechado", não "enviado".** `incerto` (compromisso `a_conferir` ou linha inexistente): não envia e NÃO fecha, reavalia a cada rodada e expira pela janela de 2 dias ou sai quando voltar a `atrasado`. Nenhum dos dois conta nos 10 por rodada; o log mostra só contagens (`N enviado(s), M obsoleto(s) descartado(s), K incerto(s)`). O produtor (`gabi.avisos`, a cada 15 min) fecha o aviso aberto quando `resolvido` e também o `incerto` mais velho que a janela de 2 dias (fechado sem envio, para poder nascer um aviso novo quando a conta voltar a `atrasado`); aviso aberto, nunca enviado e fora da janela não segura mais o aviso novo. `vence_hoje` sem item aberto mas com item `a_conferir` é `incerto`. Avisos repetidos da mesma conta (mesmo tipo e chave) são consolidados no mais recente: os antigos fecham como superados (sem envio; se já tinham sido enviados, só `entregue_em`), no produtor, no Telegram e no Hermes. Aviso já enviado cuja condição resolveu fecha só com `entregue_em` (`telegram_em` segue "enviado"). `escuta_atencao` nunca é revalidada nem expira.

## Moeda estrangeira: corrigir o histórico {#moeda-historico}

Depois da migração 0022, lançamentos antigos em USD/EUR/PEN continuam com o valor da moeda da compra gravado como reais até a ferramenta rodar. Passo de deploy **só com o OK do Ricardo**:

1. `python -m tools.corrigir_moeda --dry-run`: só lê e imprime contagens (`mudariam`, `diferenca_centavos`, `sem_bruto`). Não migra: se a 0022 ainda não foi aplicada, avisa e sai com erro.
2. `python -m tools.corrigir_moeda`: aplica, em transação única, a partir do bruto imutável (sem rede). Só toca lançamentos em moeda estrangeira, usando o bruto mais novo de cada um; BRL nunca muda. Pode rodar de novo (idempotente).
3. Conferir `sem_bruto`: ele conta TODA linha sem transação no bruto (BRL, lançamentos manuais ou importados também), não é o número de lançamentos estrangeiros que ficaram sem correção. Essas linhas não são tocadas: ficam com `moeda` vazia e `convertido=1`, então o aviso `lancamento_sem_conversao` NÃO as conta (ele só conta `convertido=0`).

Ensaio feito em 11/10/2026 numa cópia do banco real: 104 lançamentos mudariam, diferença de -R$ 49.336,08, `sem_bruto=0`, e uma segunda execução não mudou nada (0). Portanto, no banco real, `sem_bruto` deve ser 0. Se não for, pare e investigue antes de rodar sem `--dry-run`.

## Agenda do Google: consentimento, fontes e timer {#agenda}
Somente leitura (`calendar.readonly`). `python -m gabi.agenda` (unit `gabi-brain-agenda.service`, oneshot, sem rede, timer a cada 15 min das 06h às 22h BRT) lê pela ponte do serviço de fontes as fontes liberadas (`agenda_fonte.estado='sim'`) e imprime só contagens (nunca título). O instalador instala `gabi-brain-agenda.service` e `.timer` mas **não habilita**. Passos do Ricardo, nesta ordem:
1. **Consentimento de cada conta** (`resper@gmail.com`, `resper@ness.com.br`, `resper@bekaa.eu`, `backoffice@bekaa.eu`): refaça o consentimento OAuth com os DOIS escopos, `https://www.googleapis.com/auth/calendar.readonly` e `https://www.googleapis.com/auth/contacts.readonly` (o mesmo refresh token serve a contatos e agenda; se for ligar também o e-mail, inclua `gmail.modify` no mesmo consentimento, ver `{#correio}`). Em contas do Workspace (bekaa.eu) o administrador pode precisar liberar o app. **Como obter o token:** com um cliente OAuth do tipo "Computador" (o OAuth Playground não serve), rode no SEU terminal, uma conta por vez, `cd ~/gabi-brain && sudo .venv/bin/python -m tools.obter_token_google <conta> --gravar`: com o `/etc/gabi/google.env` já tendo `GOOGLE_CLIENT_ID` e `GOOGLE_CLIENT_SECRET` ele os lê de lá (sem o arquivo, pede o Client ID e o secret, este sem eco); mostra o link, você entra na conta, copia a URL final (página de erro em localhost, é normal) e cola; ele confere os escopos e, com `--gravar`, põe `GOOGLE_REFRESH_<CONTA>=...` direto no `google.env` sem mostrar o token (sem `--gravar` imprime a linha para você colar). Não grava nenhum outro arquivo. Só `oauth` tem cliente hoje; delegação por conta de serviço não está implementada.
2. **Segredos:** `/etc/gabi/google.env` (`root:root` 0600, só você mexe) com `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` e `GOOGLE_REFRESH_<CONTA>` por conta (`<CONTA>` em maiúsculas, o que não é letra/número vira `_`: `GOOGLE_REFRESH_RESPER_GMAIL_COM`, `GOOGLE_REFRESH_BACKOFFICE_BEKAA_EU`). O `google-contatos.env` antigo continua sendo lido. Depois: `sudo systemctl restart gabi-brain-fontes`. Conta sem refresh token: erro `conta não autorizada: <conta>` (esperado até o consentimento; não derruba as outras).
3. **Painel › Cadastros › Agenda:** cadastre cada conta ("Cadastrar conta", tipo Google), clique em **Descobrir calendários** e **Liberar** só os que quer ler (o principal é `primary`). Nada é lido antes de liberar. Ajustes na mesma tela: compromissos privados (`mostrar` padrão | `so_painel` | `ocultar`), fuso, dias para trás (0–60) e para frente (7–365).
4. **Hermes:** em `~/.hermes/config.yaml`, em `mcp_servers › gabi_brain › tools › include`, acrescente `- agenda_listar` e `sudo systemctl restart hermes-gateway` (lista oficial em `docs/fontes/hermes.md`; sem isto o Hermes não enxerga a agenda, só o `resumo_manha`).
5. **Ligar:** `sudo systemctl enable --now gabi-brain-agenda.timer`; primeira rodada na hora: `sudo systemctl start gabi-brain-agenda.service` e `journalctl -u gabi-brain-agenda -n 20` (linhas `agenda: fonte=… lidos=… gravados=… apagados=… pulados=… recarga=sim|nao`).
6. **Aceite com dado real (antes de confiar):** compare a SEMANA inteira do painel (Agenda) com o app do Google, nas quatro contas: (a) evento de dia inteiro aparece como "dia inteiro", sem horário; (b) evento de 22h–23h30 aparece no dia certo; (c) evento que cruza a meia-noite aparece nos dois dias; (d) cancelado some na rodada seguinte; (e) privado segue a política escolhida; (f) a mesma reunião convidada em duas contas aparece uma vez; (g) `resumo_manha` e `agenda_listar` (pergunte ao Hermes "o que tenho amanhã?") batem em horário de Brasília.
- **Falhas:** credencial recusada gera o aviso "Reconectar a agenda <conta>" no sino (1 por dia; fecha sozinho quando a conta volta a sincronizar); outros erros ficam em `ultimo_erro` na tela. O frescor tem fonte própria (`agenda`, 12 h): liberada e sem rodada boa aparece "agenda nao conferida" nos avisos de dados desatualizados.
- **Revogar:** desligue a fonte no painel (os compromissos somem das telas) e `sudo systemctl disable --now gabi-brain-agenda.timer`; para apagar o que já foi guardado: `sudo -u gabibrain sqlite3 /var/lib/gabi-brain/gabi.db "delete from agenda_evento where fonte_id in (select id from agenda_fonte where conta='<conta>'); update agenda_fonte set sync_token=null where conta='<conta>'"`; para cortar o acesso de verdade, tire o refresh token de `/etc/gabi/google.env`, reinicie `gabi-brain-fontes` e revogue o app na conta Google.

## E-mail do Google: consentimento, contas e timer {#correio}
`python -m gabi.correio` (unit `gabi-brain-correio.service`, oneshot, sem rede, timer a cada 15 min das 06h às 22h BRT) sincroniza as contas liberadas pela ponte do serviço de fontes, confere quem você já respondeu, classifica pelo modelo barato, move para a **lixeira** o obviamente inútil (só nas contas com a lixeira ligada), alerta emergências e resume o dia; imprime só contagens (nunca remetente, assunto ou trecho). O instalador instala `.service` e `.timer` mas **não habilita**. A Gabi **nunca envia, responde nem apaga de vez**: a lixeira do Gmail esvazia sozinha em 30 dias e você restaura antes. Passos do Ricardo, nesta ordem:
1. **Consentimento de cada conta** (`resper@gmail.com`, `resper@ness.com.br`, `resper@bekaa.eu`, `backoffice@bekaa.eu`): refaça o consentimento OAuth com os TRÊS escopos, `contacts.readonly`, `calendar.readonly` e `https://www.googleapis.com/auth/gmail.modify` (o mesmo refresh token serve a contatos, agenda e e-mail; se você já refez para a agenda, refaça de novo incluindo o Gmail). ## Escrita de contatos da ness (aprovada no painel) {#contatos-escrita}

3. **Revisar a fila:** Painel › Cadastros › Contatos. Cada proposta mostra antes e depois; aprove ou recuse uma a uma. O botão em lote aprova só as correções que estão na tela (o painel manda os ids exibidos; nunca as criações, nem o que chegou depois). **Correção = a normalização muda os DÍGITOS do celular** (caso típico: celular antigo de 8 dígitos que ganha o 9); diferença só de formatação (espaço, hífen, parênteses, `+55`, zero de discagem) não gera proposta. 4. **Aprovar** o que quiser. Aprovada ainda não escreve nada e pode ser desfeita: a lista "Aprovadas aguardando gravação" tem **Recusar** em cada linha (vale até a gravação acontecer; `aplicada`, `recusada` e `falhou` não mudam mais).
5. **Ligar o interruptor** só depois: `sudo -u gabibrain sqlite3 /var/lib/gabi-brain/gabi.db "insert into parametro(chave, valor) values ('contatos.escrita', '\"ligado\"') on conflict(chave) do update set valor=excluded.valor"` (valor JSON; qualquer outro valor, ou a linha ausente, é desligado). Para gravar, rode `sudo systemctl start gabi-brain-contatos` (sincroniza e logo depois aplica); com o timer desligado (padrão do `instalar.sh`) nada acontece sozinho.
6. **Desligar:** `sudo -u gabibrain sqlite3 /var/lib/gabi-brain/gabi.db "delete from parametro where chave='contatos.escrita'"` (ou grave `'\"desligado\"'` com o mesmo comando do passo 5). Vale já na próxima rodada; propostas aprovadas ficam esperando, intactas.
7. **Conferir (só contagens):** `journalctl -u gabi-brain-contatos -n 20`. A linha `contatos-gravar: escrita=ligada|desligada aprovadas=N simuladas=N aplicadas=N falhas=N descartadas=N` não traz nome nem número; `ja_em_execucao=1` quer dizer que outra rodada estava em curso.
- **Propostas `falhou` (coluna `motivo`):** `contato_alterado` = o contato mudou no Graph (ou no banco) depois da proposta; nada foi escrito, e a próxima sincronização gera outra se ainda fizer sentido. `contato_alterado` também aparece quando, antes de criar, o remetente deixou de estar aprovado (ou foi renomeado) ou quando a conta saiu de `escuta.contas_contatos`. `ja_existe` = o número já está em algum contato já sincronizado (Graph ou Google), em qualquer conta (criação duplicada evitada). Limite aceito: contato guardado numa SUBPASTA de contatos do Outlook não vem no `/contacts` do Graph; criar o mesmo número pode duplicá-lo. `graph_indisponivel` = a ponte ou o Graph falhou (rede, 4xx/5xx, resposta inválida); o `journalctl` mostra só que houve falha, e a rodada sai com código 1. Proposta que você recusou fica como `recusada` (estado, sem motivo) e a Gabi não a propõe de novo.
- **Rodada repetida:** não rode `python -m gabi.contatos.contatos_gravar` à mão várias vezes seguidas depois de uma falha de banco; use o timer/serviço, que sincroniza antes.
- **Limpeza (ADR-021):** a fila ganha `corrigir_nome` (tira só lixo do nome), `apagar_telefone` (telefone que não é número; estrangeiro com DDI ≠ 55 passa a ser válido) e `apagar_contato` (nome de 1 caractere, 1 telefone, sem e-mail). Apagar é irreversível no Graph: aprove um a um (o lote só pega correções) e confirme. Migração 0073 vem com `instalar.sh`. **Atenção:** com `contatos.escrita` ligado, aprovar já é decidir gravar na próxima rodada do `gabi-brain-contatos` (timer diário 10:00) ou em `systemctl start gabi-brain-contatos`.

## Documentos: leitura do Paperless, aprovação e vencimentos {#documentos}
Decisão: `docs/adr/027-documentos.md`; spec: `docs/superpowers/specs/2026-10-23-documentos-design.md`. Instalar e rodar a primeira vez: `sudo ~/instalar-documentos.sh` (instala o brain, mostra a migração 0081, as contagens copiadas da família, dispara uma rodada, dá ao Hermes as ferramentas novas e imprime só contagens). Depois: aba Documentos (`#cadastros/documentos`), aprovar ou recusar cada proposta.
- **Hermes (o script faz os passos 1 a 4; à mão, se preciso):** 1. backup: `cp -p ~/.hermes/config.yaml ~/.hermes/config.yaml.bak-antes-documentos`; 2. em `~/.hermes/config.yaml` (`mcp_servers › gabi_brain › tools › include`) acrescentar `documentos_consultar`, `documentos_vencimentos` e `bens_listar` (lista oficial em `docs/fontes/hermes.md`, 29 ferramentas; o escopo `familia` do token já cobre as três); 3. SOUL novo: `bash ~/gabi-brain/deploy/instalar-hermes-soul.sh` (como `ricardo`); 4. `sudo systemctl restart hermes-gateway`; 5. `/new` no Telegram **e** no WhatsApp (a conversa velha não vê as ferramentas novas). Conferir: pergunte ao Hermes o número de um documento; ele responde com o link do painel.
- **Timer:** `gabi-brain-documentos.timer`, diário às 05h (Brasília). Uma rodada à mão: `sudo systemctl start gabi-brain-documentos`; ver: `journalctl -u gabi-brain-documentos -n 20` (linha `documentos: lidos=N propostas=N sem_texto=N sem_documento=N falhas=N`, sem número nem texto).
- **Sem chave de modelo:** a rodada sai 0 sem ler nada. O aviso fica em `rodada.erro` (`parada: ...`): `sudo -u gabibrain sqlite3 /var/lib/gabi-brain/gabi.db "select id, status, lidos, novos, erro from rodada where fonte='documentos' order by id desc limit 5"`.
- **Parâmetros** (`parametro`, valor JSON): `documentos.max_por_rodada` (padrão 50 documentos), `documentos.max_caracteres` (padrão 12000 do OCR enviados ao modelo), `documentos.avisar_dias` (padrão `[60,30,7]`). Ex.: `sudo -u gabibrain sqlite3 /var/lib/gabi-brain/gabi.db "insert into parametro(chave, valor) values ('documentos.max_por_rodada', '100') on conflict(chave) do update set valor=excluded.valor"`. O custo do modelo entra no teto diário do correio.
- **Reprocessar um documento:** apagar a linha dele em `documento_leitura` (pelo `paperless_id`); a próxima rodada lê de novo: `sudo -u gabibrain sqlite3 /var/lib/gabi-brain/gabi.db "delete from documento_leitura where paperless_id=<id>"`. Estados `falhou` já são retentados sozinhos (até 3 vezes).
- **Número "as is":** o número só vira proposta se aparece no OCR; se o OCR errou uma letra, corrija na aprovação olhando o documento.
- **Desfazer (rollback):** ⚠️ perde tudo o que foi aprovado, recusado ou lido depois da instalação (documentos novos, bens, propostas e leituras); a família volta ao estado de antes da 0081. 1. `sudo systemctl stop gabi-brain-documentos.timer gabi-brain-api gabi-brain-mcp`; 2. backup do banco (`sudo -u gabibrain sqlite3 /var/lib/gabi-brain/gabi.db ".backup /var/lib/gabi-brain/gabi.db.antes-rollback-documentos"`); 3. no banco, numa transação: `drop view familia_proposta; drop view familia_documento; drop table documento_leitura; drop table documento_proposta; drop table documento_data; drop table documento_numero; drop table documento; drop table bem; alter table pessoa_documento_legado rename to pessoa_documento; alter table pessoa_proposta_legado rename to pessoa_proposta; delete from schema_versao where nome='0081_documentos.sql';` (o mesmo no cabeçalho de `migrations/0081_documentos.sql`); 4. voltar o código para a main de antes do merge (`git revert` do merge de `feat/documentos` em `~/gabi-brain`) e `sudo ~/instalar-brain.sh` — sem isso a API aplica a 0081 de novo ao subir; 5. Hermes: `cp -p ~/.hermes/config.yaml.bak-antes-documentos ~/.hermes/config.yaml`, `sudo systemctl restart hermes-gateway` e `/new`.
- **Limite:** apólice, contrato e outro podem coexistir; um mais novo do mesmo titular e tipo fecha o aviso do outro.
